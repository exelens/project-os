## 1. Зачем

Рядом (если есть) живут соседние продукты / адаптеры. Нужно не путать:

- где SSOT своего домена;
- куда можно писать код;
- когда выносить правило из роута / хендлера.

Чужие данные **подтягиваем** (read / ссылка), не забираем в общую базу и не копируем чужой SSOT.

## 7. Код: сейчас и later

**Сейчас:** роуты + schemas + persistence (или аналог стека). Лёгкий DDD = словарь + границы + инварианты.

**Выносить из хендлера**, когда: правило в двух местах; god-route мешает peel ([`../prism/ArchitectureCheck.md`](../prism/ArchitectureCheck.md)).

**Не заранее:** Entity/VO/Repository «как в книге», domain events между репо, общий kernel, rewrite ради DDD на L0.

Если продукт — аналитика с конвейером фактов, слои данных опиши отдельно (ingest → … → UI) и ссылкой из §2; не смешивай с trust-contours (зерно цифр ≠ pipeline).
