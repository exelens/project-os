## Тон (переносимо)

- Спокойно и по делу — без давления и без «как для идиота».
- Одна мысль на блок (hero ≠ список фич).
- Действие важнее CRUD-сущности («Сделать X», не «Создать объект»).
- Честность: claim только с evidence в коде/доках; иначе — [accepted-debt.md](accepted-debt.md) или снять copy.
- Без shell / env / путей скриптов на клиентских экранах.

## Правила написания

1. Без эха (не одно и то же слово в hero и подзаголовке подряд).
2. Императив один раз — либо headline, либо CTA.
3. Кнопки — глагол результата, не канцелярит.
4. Ошибки API — короткий `detail`, не стек и не сырой HTTP status text.
5. Инсайты / подсказки: факт → гипотеза → действие (если продукт так устроен); без недоказуемых «мы увидели X».

---

## Антипаттерны

- Жаргон домена на первом экране без перевода.
- Обещание результата / «гарантия» без evidence.
- Инструкции разработчика в UI.
- Второй файл «voice/vision» в чате или соседнем доке — править **здесь**.

## Как менять

1. Смысл / тон / словарь → этот файл.  
2. Экран → UI + при смене эталона first screen — лок-тест copy (TODO_COPY_LOCK_TEST).  
3. Новые лейблы продукта → строка в [canon-owners.md](canon-owners.md), не только сюда.  
4. Коротко отметить в changelog / AGENTS продукта, если менялся канон.
