# Конвенции агента (стеко-нейтральные)

1. **Канон > чат.** Правда в коде и коротких docs; чат не SSOT.
2. **Один owner на понятие.** Сначала таблица canon-owners, потом правка.
3. **Границы контекста.** Перед правкой — `docs/light-ddd.md` (своё / чужое / куда писать); GO / режим этапа — блок в `AGENTS.md`.
4. **Малый diff.** Не рефакторить соседнее «заодно»; не плодить файлы без нужды.
5. **Тест рядом с риском.** Нет теста — добавь тонкий; не раздувай suite близнецами. Чистая логика → Hypothesis (или аналог); публичный API → Schemathesis отдельно от fast CI; KPI/пороги → точечный mutation по боли (`tests/README.md`).
6. **Evidence.** «Готово» только после команды проверки или честного «не прогнал, потому что…».
7. **Секреты.** Не коммить `.env`, токены, дампы prod.
8. **Время.** Единый helper / TZ-политика репо — не deprecated API наугад.
9. **DB sessions.** Не открывать вторую сессию, если caller передал существующую.
10. **Ошибки.** Клиенту — безопасное сообщение; в лог — `exception` / `exc_info`.
11. **Prism.** Audit/merge/verify не меняют код; wipe reviews — только человек.
12. **Post-code loop.** После любой задачи: (a) покрыть затронутый контур тестами, (b) актуализировать docs, (c) re-run тесты на актуальность. Три шага — один чат, не три разных сессии.
13. **Vibe-check (по желанию).** После задачи: спросить «какие скрытые риски, вопросы, предложения?» — агент анализирует diff и предлагает доп. шаги.
14. **UI copy.** Тон / словарь витрины и кабинета — `docs/voice.md` (если файл есть). Claim без evidence не писать; shell/env не в клиентский UI.
15. **Короткий AGENTS.** Статус / режим / навигация — да; летопись ID и «что чинили в октябре» — нет.
